# blaze-cache-wasm — v0.2.0 project plan

**Version:** `0.2.0`
**Date:** 2026-11-24
**Status:** proposed — blocked by ADRs D1, D2, D3, D6, D7; no code started
**Repository:** standalone Rust crate (this repository)
**Relates to:** [Roadmap to adoption](ADOPTION-ROADMAP.md) (Phase 1), [v0.1.0 plan](0.1.0.md), [ADR-0001](../decisions/0001-abi-strategy.md), [`blaze.loom` v1](../decisions/blaze.loom), [M3 spike](../decisions/m3-spike.md)

## Why 0.2.0 exists

0.1.0 delivered a decision, not a cache: one export (`__blaze_abi_version()`), a frozen v1 schema
and green baselines. Its tag (`0f3da91`) is the immutable anchor for `loom-abi-v1`.

0.2.0 is the first release that can **create a cache and answer `get`/`set`/`has`/`delete`/`stats`**
through the flat ABI, in this repo, with no `wasm-bindgen` and no `unsafe` blocks. It is the engine
and ABI half of adoption; the generator, npm package, full method parity and monorepo switch belong
to 0.3.0–0.5.0 (see the [Roadmap to adoption](ADOPTION-ROADMAP.md)).

The shape of 0.2.0 is fixed by the roadmap's Phase 1. This plan adds the concrete contract needed
to implement it without drift.

## Evidence gathered since the roadmap was written

The engine was inspected at `../blaze-cache`, branch `v0.5.0-beta.1`, commit
`bf0bf2781e2f4ae34f0eab6b9776f79bc76fa8d1` (clean tree). These facts change the v1 schema and must
be settled in the ABI ADR rather than discovered during implementation:

| Finding | Consequence for 0.2.0 |
|---|---|
| `blaze-cache-core` is `Cache<K, V>` generic over `V` with **no `Clone` bound** on the hot path (`cache.rs:151`). | The wasm layer can choose its own value type; `Ref` handles and bytes are both viable without touching the core. |
| The core has **no `EvictionPolicy` type**. Eviction is a fixed SIEVE implementation (`eviction.rs:25`). D6's "add `Sieve`" must be a *schema* enum with one variant, not a claim of configurable LRU/LFU/FIFO. | `enum EvictionPolicy { Sieve }` in v2; Lru/Lfu/Fifo are removed, not implemented. |
| The real struct is `CacheStats` (`stats.rs:9`) with **7 fields**: `hits`, `misses`, `evictions`, `expirations`, `invalidations`, `size: usize` (live **entries**), `capacity: usize` (max **entries**). There is no `bytes` or `entries` field. | v1 `Stats { hits, misses, evictions, bytes, entries }` is wrong. v2 uses the 7-field superset; `bytes`/`entries` are dropped, not invented. |
| The core is configured by `Cache::new(capacity: usize)` — an **entry count**, not `max_bytes` (`cache.rs:155`). TTL is per-entry via `EntryOptions` (`entry.rs:20`), not a cache-wide config field. | v1 `CacheConfig { max_bytes, ttl_ms, eviction }` cannot be implemented as written. v2 config is `{ capacity, eviction }`; TTL moves to the `set` call (already in the roadmap's signature). |
| The core already has a safe byte arena (`bytes.rs`): `BytesRef`, `Reservation`, `reserve_for_host`, `copy_into`, `to_vec`, with pointer validation in safe Rust. | Candidate for the `view<buffer>` value path. Validate its `Drop`/region-return semantics in M2; fall back to an owned `Vec<u8>` in this crate if they conflict with cache lifetime. |
| The legacy wasm crate uses `Value::{Ref(JsValue), Bytes(BytesRef)}` (`blaze-cache-wasm/src/lib.rs:52`) and a JS-authoritative id mode where the real object lives in a JS `Map<id, V>`. | Confirms D2: wasm should store a `u32` handle, JS owns the object. 0.2.0 needs only a test-side `Map`; the `FinalizationRegistry` runtime is 0.3.0. |
| The legacy crate proves the raw-key pattern: `ensureScratch`/`ensureTagScratch` allocators plus `with_raw_key`/`with_raw_tags`/`with_raw_keys` bounds checks that **degrade to miss/no-op instead of trapping**. | Reuse this exact shape for the flat arena exports (§ "Safety model"). |
| Core dependencies: `foldhash 0.2`, `serde 1` (derive), `web-time 1.1`, `smallvec 1` (serde). Workspace-inherited package fields, edition 2024, `rust-version 1.85`, `#![forbid(unsafe_code)]`, std-only, no wasm-specific `cfg`. No publish gate and no crate publishing in CI. | Extraction needs version/edition/license inlining and a version pin; vendoring needs the same inlining plus a sync script. Both are mechanical, not redesigns. |

`ABI_VERSION` stays `1` for the whole 0.2.0 line; any signature change after tagging bumps to `2`
in 0.3.0 (where the roadmap already plans a bump).

## Scope of 0.2.0

1. **ADRs first.** Settle D1, D2, D3, D6 and D7 as decision records and update `docs/README.md`.
2. **Engine in this repo.** Extract or vendor `blaze-cache-core` with no dependency on
   `../blaze-cache/crates/*`, pinned to the commit above and recorded in `engine-provenance.md`.
3. **`loom-abi-v2`.** A new schema file; v1 stays frozen. `ABI_VERSION = 1`, checked in Rust, JS
   and CI. ADR-0001 gains a v2 section instead of being rewritten.
4. **Flat exports.** Arena, cache open/close, `get_sync`/`set`/`has`/`delete`/`stats`, generation
   counter, one stable error-code enum. All host pointers copied in and bounds-checked in safe Rust.
5. **Tests.** Host fuzz/property tests for hostile pointers and lengths; wasm build + `wasm-opt -Oz`;
   a JS harness that round-trips a key, a `Ref` handle and bytes end to end.
6. **Release.** Tag `0.2.0` once every gate is green, and record the tag commit here.

## Non-goals for 0.2.0

* The Loom generator, `bindings.mjs`, `index.d.ts`, `package.json` or any npm artifact (0.3.0).
* `FinalizationRegistry`, `AbortSignal`/`get()` orchestration and the typed `BlazeCache` class (0.3.0, D4).
* The other ~50 methods used by `packages/core/src/cache.ts` — ids, tags, query, bytes scratch,
  drop log, batch ops (0.4.0; tracked in `docs/parity.md`).
* Browser matrix, Playwright and performance budgets vs wasm-bindgen (0.4.0).
* Any change to the monorepo, its public API or its `engine` option (0.5.0).
* Async, cancellation or reentrancy *inside* wasm. The v2 schema declares `get` as async, but it
  lowers to the TS runtime in 0.3.0 (D4); 0.2.0 exports only the sync subset.
* `max_bytes` budgets and an actual LRU/LFU/FIFO policy. The core does not implement them.

## ABI v2 contract

`docs/decisions/blaze-v2.loom` is added; `docs/decisions/blaze.loom` stays byte-for-byte as tagged
in 0.1.0. The v2 schema declares the full high-level `Cache` resource (including async `get`), but
only the sync subset below has wasm exports in 0.2.0.

**Config encoding** — 8 bytes, little-endian, two `u32` slots:
`capacity: u32` (max entries, clamped to ≥1 by the core), `eviction: u32` (`0 = Sieve`). No
`max_bytes`, no cache-wide TTL: both are unimplementable with the pinned core.

**Value kinds** for `set`: `0 = Ref` (a `u32` handle in `value_ref_or_ptr`, `value_len` ignored),
`1 = Bytes` (arena pointer in `value_ref_or_ptr`, byte length in `value_len`). TTL is per-entry:
`ttl_ms = 0` means no TTL, otherwise a `Duration`.

**Tags encoding** — flat buffer of repeated `[u32 byte_len][UTF-8 bytes]` records; zero-length
buffer means no tags.

**Stats layout** — 56-byte fixed struct, seven little-endian `u64` fields in this exact order:
`hits, misses, evictions, expirations, invalidations, size, capacity`. `size` and `capacity` are
**entry counts**. No `bytes` or `entries` field exists to expose.

**Error codes** — one stable `i32` enum, asserted in the schema and in tests:

| code | name | meaning |
|---:|---|---|
| 0 | `OK` | operation succeeded |
| 1 | `MISS` | key absent or expired |
| 2 | `BAD_ARG` | bad id, out-of-bounds pointer/length, malformed config/tags, unknown kind |
| 3 | `STALE_VIEW` | generation advanced or `memory.buffer` swapped since the view was taken |
| 4 | `CLOSED` | cache id was closed |
| 5 | `OOM` | arena allocation failed |

No panic crosses the boundary; release keeps `panic = "abort"`. Unsupported inputs return
`BAD_ARG`, never a trap or a silent no-op that looks like success.

**Generation rule** — each cache has a `u64` generation incremented on every mutation (`set`,
`delete`, `clear`, `close`). `__blaze_generation(id) -> u64` returns `0` for an unknown id. A
returned view is valid only until the next mutation or a `memory.grow`; the runtime (0.3.0) checks
the generation before dereferencing and raises `LoomError('StaleView')` on mismatch.

## Flat export surface

| Export | Signature | Notes |
|---|---|---|
| `__blaze_abi_version` | `() -> u32` | returns `1`; still the first call the host makes |
| `memory` | wasm memory export | unchanged |
| `__blaze_arena_alloc` | `(len: u32) -> u32` | aligned arena pointer, `0` on failure; host writes key/value bytes here |
| `__blaze_cache_open` | `(config_ptr: u32, config_len: u32) -> i32` | `>= 0` cache id; negative `-code` on failure |
| `__blaze_cache_get_sync` | `(id: u32, key_ptr: u32, key_len: u32, out_ptr: u32, out_cap: u32, out_len_ptr: u32) -> i32` | `OK` writes byte length to `out_len_ptr`; `out_ptr = 0, out_cap = 0` probes length only |
| `__blaze_cache_set` | `(id: u32, key_ptr: u32, key_len: u32, kind: u32, value_ref_or_ptr: u32, value_len: u32, ttl_ms: u64, tags_ptr: u32, tags_len: u32) -> i32` | increments generation on success |
| `__blaze_cache_has` | `(id: u32, key_ptr: u32, key_len: u32) -> i32` | `OK` / `MISS` |
| `__blaze_cache_delete` | `(id: u32, key_ptr: u32, key_len: u32) -> i32` | `OK` / `MISS`; increments generation on removal |
| `__blaze_cache_stats` | `(id: u32, out_ptr: u32, out_cap: u32) -> i32` | writes the 56-byte stats struct |
| `__blaze_cache_close` | `(id: u32) -> i32` | consumes the id; increments generation |
| `__blaze_generation` | `(id: u32) -> u64` | `0` for unknown ids |

`get_sync` adds an `out_len_ptr` argument to the roadmap's sketch. Without it the single `i32`
return would have to encode both an error and a byte length; keeping the error enum pure is worth
one extra bounds-checked out pointer. The schema, ADR-0004 and `js/abi-check.mjs` must all use this
final signature.

## Safety model

* `#![deny(unsafe_code)]` with the same single documented `#[no_mangle]` attribute exception as
  0.1.0. No `unsafe` blocks or calls, including in the engine.
* Every host `(ptr, len)` is validated against the arena **before** any read or write; input is
  copied into Wasm-owned storage, never borrowed as a Rust slice. Oversized lengths and reentrant
  allocation return `BAD_ARG`/`OOM` instead of growing unchecked.
* Follow the legacy crate's degradation rule: bad scratch pointers produce a miss or no-op, never
  a trap and never a fabricated success.
* `Ref` handles are opaque `u32`s to wasm. It does not dereference, guess or reuse them; handle
  allocation and recycling remain the host's responsibility.
* `js/abi-check.mjs` is extended to assert the **exact export set**, `ABI_VERSION = 1`, error-code
  constants and the generation export. Skew throws rather than misdecoding.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Extraction stalls (D1) | Vendor the pinned snapshot first behind `scripts/sync-core.sh`; extraction becomes a dependency bump, not a rewrite. |
| `BytesRef` `Drop` returns regions to a thread-local arena, conflicting with cache-owned values | Validate in M2; if it conflicts, use an owned `Vec<u8>` value variant in this crate and keep the arena only for host input/output. |
| Another schema-vs-core mismatch surfaces (e.g. TTL semantics, id mode) | M2 compares every v2 schema entry to a core method before M3; mismatches become ADR-0004 amendments, not silent mappings. |
| Handle table leaks JS objects (D2) | Document that 0.2.0 is wasm-side only; the `Map` in the harness is disposed explicitly; `FinalizationRegistry` is required by the 0.3.0 browser leak test. |
| Hostile pointers trap the module | Property tests over random `u32` pointers/lengths, zero/max keys, reentrant alloc; all must return an error code. |
| `web-time` or edition 2024 breaks the wasm build | Build both targets in M2 before writing exports; pin the exact upstream commit in `engine-provenance.md`. |
| Monorepo is mid-beta (`v0.5.0-beta.1`) | Pin the commit, do not track its branch; no monorepo changes until Phase 4 after `0.5.0-rc.1`. |
| Schema drift after tagging | `ABI_VERSION` bumps to `2` in 0.3.0 for any signature change; v1 and v2 files are archived history. |

## Verification (same gate as 0.1.0, extended)

* `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --locked`.
* `cargo build --target wasm32-unknown-unknown` and `--release`, then `wasm-opt -Oz`.
* `node js/abi-check.mjs` against the release module: export set, `ABI_VERSION = 1`, error codes,
  generation export; a deliberately wrong version must throw.
* `cargo tree` proves no monorepo crate dependency; `cargo package --list` still excludes `spike/`.
* Host property tests in `tests/abi.rs` for hostile pointers, zero/max-length keys, malformed
  config/tags, reentrant allocation and closed ids.
* A JS harness instantiates the release wasm, allocates a key, `open` → `set` (a `Ref` handle and
  a bytes value) → `get_sync` → `has` → `stats` → `delete` → `close`, with no wasm-bindgen.

## Definition of done

`0.2.0` is done when the crate can create a cache and round-trip a `Ref` and a bytes value through
the flat ABI in both Rust tests and a JS harness, the v2 schema and all five ADRs are committed, the
gate is green, and the tag is the immutable anchor for `loom-abi-v2`. Full method parity, generated
bindings and installable packages are explicitly *not* required until 0.3.0–0.4.0.
